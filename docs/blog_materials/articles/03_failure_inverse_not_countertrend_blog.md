# 「失敗している人の逆をやる」は逆張りではない

作成日: 2026-06-01  
用途: ブログ記事下書き

## この記事で伝えること

トレード研究をしていると、よくこう考えます。

```text
負けている人が多いなら、その逆をやれば勝てるのでは？
```

この考え方には、大きなヒントがあります。

ただし、ここで注意が必要です。

> 失敗している人の逆をやるとは、売買方向を逆にすることではありません。

買って負けている人が多いから売る。  
売って負けている人が多いから買う。

そう単純に考えると、ただの逆張りになってしまいます。

本当に見るべき逆は、方向ではなく、**行動の逆** です。

## 失敗の逆とは何か

失敗している人に多い行動は、だいたい次のようなものです。

```text
抜けた瞬間に入る
急変に反応する
ローソク足1本だけで判断する
損切り位置を決めずに入る
負けた後に取り返そうとする
```

この逆は、売買方向を反対にすることではありません。

本当の逆はこうです。

| 失敗しやすい行動 | 逆にする行動 |
|---|---|
| 抜けた瞬間に入る | 抜けた後に戻らないか待つ |
| 急変に反応する | 急変後の落ち着きを見る |
| ローソク足1本で決める | 節目、上位足、次足を確認する |
| 損切り位置なしで入る | 入る前に否定ラインを決める |
| 取り返そうとする | 次の形が整うまで何もしない |

これが「失敗の逆利用」です。

## 例1: ブレイク飛び乗りの逆

よくある失敗は、抵抗線を抜けた瞬間に買うことです。

```text
抵抗線を上抜け
-> すぐ買う
-> 直後に戻される
-> 損切り
```

では、この逆は「すぐ売る」ことでしょうか。

違います。

逆にするべきなのは、方向ではなくタイミングです。

```text
抵抗線を上抜け
-> すぐ入らない
-> 押し戻りを待つ
-> 抜けたラインの外側で止まるか見る
-> 再加速が出てから候補にする
```

これが本当の逆です。

## 例2: 急落後の売りの逆

急落を見ると、人は「まだ下がる」と思いやすくなります。

```text
大陰線
-> 安値更新
-> まだ下がると思って売る
-> 下がらず反発
-> 踏み上げで損切り
```

この逆は、急落した瞬間に買うことではありません。

本当の逆は、売り手が苦しくなるまで待つことです。

```text
急落
-> すぐ売らない
-> すぐ買わない
-> 安値更新できない時間を見る
-> 安値圏で棚を作る
-> 棚高値を抜けたら候補として確認する
```

大事なのは、反対方向に賭けることではなく、片側の期待が失敗したことを確認することです。

## 例3: ローソク足1本判断の逆

長いヒゲや大陽線、大陰線を見ると、人はすぐ意味をつけたくなります。

```text
長い下ヒゲが出た
-> 反転だと思って買う
```

でも、ヒゲ1本だけでは足りません。

逆にするなら、こうです。

```text
長い下ヒゲが出た
-> すぐ買わない
-> 次の足で安値を守るか見る
-> 節目と上位足を確認する
-> 損切り位置が近いなら候補
```

ローソク足は大事です。

でも、1本の足だけで「答え」にしてはいけません。

## 失敗の逆利用は待つ技術

失敗の逆利用を一言でいうなら、こうです。

> 反応を遅らせる技術。

多くの人が反応したくなる場所で、すぐ入らない。  
そのあと、何が残るかを見る。

これが、失敗データを活かす一番現実的な方法です。

## STOP、WAIT、CHECKに変換する

失敗の逆利用は、次の3段階にすると使いやすくなります。

| 段階 | 意味 |
|---|---|
| STOP | 多くの人が反応しやすい場所 |
| WAIT | 反応後の値動きを見る場所 |
| CHECK | 待った後に条件を確認する場所 |

失敗している人が入った場所は、いきなりエントリー候補にしません。

まず `STOP` として扱います。

```text
ここは人が入りたくなる場所
だからこそ、すぐ入らない
```

その後、値動きが落ち着いて、節目の外側に残るなら `WAIT`。

さらに、損切り位置が近く、上位足とも合うなら `CHECK`。

この順番が大事です。

## 今日の観察ポイント

失敗している人の逆をやるとは、逆方向に入ることではありません。

今日覚えるなら、この一文です。

> 逆にするのは方向ではなく、反応の早さ。

早く入った人が負けているなら、自分は遅らせる。  
根拠が少ない人が負けているなら、自分は確認を増やす。  
損切り位置がない人が負けているなら、自分は先に否定ラインを見る。

これが、失敗データを成功に変える考え方です。
