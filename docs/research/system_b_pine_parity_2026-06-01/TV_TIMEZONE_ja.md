# B06 — TVの「時間ズレ」について（UTC vs JST）

## 結論

**ロジックのズレではなく、表示タイムゾーンの差です。**

| 列 | 意味 |
|----|------|
| `signal_time` / `entry_time` | CSVの UNIX → **UTC** のバー始値 |
| `signal_time_tv` / `entry_time_tv` | **UTC + 9時間**（チャート右下が UTC+9 のとき） |
| ストラテジーテスター「日時」 | ほぼ **`entry_time_tv`** と一致 |

価格（entry / SL / TP）は UTC でも JST でも **同じ数値**。

## AUDJPY 例（スクリーンショット照合）

| # | entry UTC (CSV) | **entry TV (JST)** | テスター entry | 価格 |
|---|-----------------|-------------------|----------------|------|
| 11 | 2023-07-25 **05:00** | **14:00** | 14:00 @ 95.596 | Py 95.594 ✓ |
| 10 | 2021-07-06 **05:00** | **14:00** | 14:00 @ 83.792 | Py 83.790 ✓ |
| 9 | 2021-04-06 **01:00** | **10:00** | 10:00 @ 84.405 | Py 84.403 ✓ |
| 8 | 2020-07-20 **01:00** | **10:00** | 10:00 @ 75.069 | Py 75.067 ✓ |
| 7 | 2020-05-14 **21:00** | **翌06:00** | 06:00 @ 69.299 | Py 69.297 ✓ |

## 照合のしかた

1. **テスター** → `entry_time_tv` 列と比較（±2時間以内で OK）
2. **チャートの「棚B」ラベル** → `signal_time_tv` のバーを見る（UTC のまま見ない）
3. CSV の `signal_time` だけ見ると **常に9時間ずれて見える**（正常）

## 変換式

```
entry_time_tv = entry_time + 9時間   （チャート設定が UTC+9 の場合）
```

チャートを UTC 表示に変えた場合はオフセット 0。右下のタイムゾーン表示を必ずメモ。

再生成: `python3 scripts/run_b06_tv_oanda_parity.py`（`*_tv` 列付き CSV）
